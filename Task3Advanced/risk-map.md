# Карта рисков трансформации «Будущее 2.0»

## Условные обозначения

- **Вероятность**: Н — низкая, С — средняя, В — высокая
- **Влияние**: Н — низкое, С — среднее, В — высокое

---

## Архитектурные риски

| № | Риск | Вероятность | Влияние | Описание |
|---|------|-------------|---------|----------|
| R1 | Потеря данных при миграции из Legacy DWH | С | В | При CDC-репликации возможна потеря или дублирование записей из-за неконсистентности схемы SQL Server 2008 |
| R2 | Несовместимость протоколов событий между доменами | С | С | Разные домены могут использовать разные форматы/схемы событий, что приведёт к ошибкам интеграции |
| R3 | Деградация производительности Event Bus при масштабировании | С | В | При увеличении числа доменов и источников Kafka может не справляться с пропускной способностью |
| R4 | Утечка данных через витрину самообслуживания | Н | В | Неправильная настройка RBAC в Data Marketplace может привести к доступу к чувствительным данным |
| R5 | Зависимость от одного облачного провайдера (vendor lock-in) | С | С | Yandex Cloud — единственный провайдер, что создаёт риски при изменении тарифов или регуляторных требований |
| R6 | Несоответствие требованиям регуляторов (ЦБ, Минздрав) | С | В | Медицинские и финансовые данные требуют соответствия 152-ФЗ, PCI DSS, иным стандартам |

---

## Организационные риски

| № | Риск | Вероятность | Влияние | Описание |
|---|------|-------------|---------|----------|
| R7 | Сопротивление команды переходу на новую архитектуру | С | С | Команды, работавшие с DWH и PowerBuilder, могут не принять событийную архитектуру |
| R8 | Нехватка компетенций по Kafka, Flink, Data Mesh | В | В | В организации мало инженеров с опытом event-driven архитектуры |
| R9 | Конфликт границ доменов между бизнес-подразделениями | В | С | Разные подразделения могут по-разному видеть границы своих доменов, что затруднит выделение Data Products |
| R10 | Распыление команды на параллельные инициативы | С | С | Одновременная интеграция фармацевтики и электроники может отвлечь ресурсы от core-доменов |
| R11 | Потеря бизнес-логики, зашитой в Legacy DWH | В | В | Значительная часть бизнес-логики реализована в хранимых процедурах SQL Server — её необходимо выявить и перенести |

## Технологические риски

| № | Риск | Вероятность | Влияние | Описание |
|---|------|-------------|---------|----------|
| R12 | Инциденты при параллельной работе двух систем (легаси + новая) | С | В | Во время миграции обе системы должны работать синхронно, что увеличивает поверхность сбоев |
| R13 | Нестабильность CDC из SQL Server 2008 | В | С | SQL Server 2008 не поддерживает современные CDC — придётся использовать триггеры или логирование транзакций |
| R14 | Потеря событий при сбое Kafka | Н | В | При неправильной настройке репликации и retention возможна потеря событий |
| R15 | Рост затрат на инфраструктуру при масштабировании | С | С | Хранение и обработка потоковых данных в облаке может привести к неконтролируемому росту затрат |
| R16 | Задержки в near-real-time обработке | С | С | При высокой нагрузке латентность обработки Flink может превысить допустимые SLA |
